# 学生身份与切换 — 实施方案（v1，2026-11-06）

> 需求：①主界面显示「当前学生」标识并支持切换 ②设置中完善用户专属信息。
> 结论先行：**复用 profiles 账套机制作为"多学生"骨架**，补上"学生身份层" + 主界面标识/切换 UI + 设置编辑页 + AI 个性化注入，四块拼齐。

## 一、现状盘点（为什么这样设计）

| 已有 | 位置 | 说明 |
|---|---|---|
| 多账套机制 | `src-tauri/src/profiles.rs` | 每账套独立数据根（数据库/VFS/凭证全隔离），注册表 `profiles.json`，切换 = 写标记 + `app.restart()` 重启 |
| 5 个 Tauri 命令 | profiles.rs:227-336 | `profile_list / create / rename / delete / switch` |
| 账套管理页 | `src/features/settings/components/ProfilesTab.tsx` | 已有创建/重命名/删除/切换 UI（含"当前使用"Badge、重启中提示） |
| 学习者画像 | `crates/dstu-memory/src/memory/learner_profile.rs` | `LearnerProfile`（薄弱点/偏好/目标），自动注入会话 system prompt |
| 侧栏底部条 | `src/components/ModernSidebar.tsx:1436-1504` | `mt-auto` 固定底部的 AppMenu 条，放学生标识的最佳位置 |

| 缺失 | 本方案补齐 |
|---|---|
| 账套无学生身份字段（仅 name） | `ProfileMeta` 扩展可选学生字段 |
| 主界面无当前学生标识 | 侧栏底部学生条 + 切换弹层 |
| 设置无身份编辑 | ProfilesTab 升级为"学生档案"编辑 |
| 画像不含身份层 | LearnerProfile 注入时携带身份 |
| 全应用无全局年级配置 | 学生年级作为单一事实源，作文批改 `grade_level` 默认值联动 |

**不做**：免重启热切换（数据根隔离决定必须重启，强行做风险大）；家长/教师角色模式（超出本次范围）。

## 二、数据层设计

### 2.1 ProfileMeta 扩展（serde default 向后兼容，旧注册表零迁移）

```rust
pub struct ProfileMeta {
    pub id: String,
    pub name: String,              // 账套名（管理用，保留）
    // ── 新增学生身份字段（全部 Option，缺省 None）──
    #[serde(default)]
    pub student_name: Option<String>,      // 学生姓名（展示用，≤20 字符）
    #[serde(default)]
    pub grade: Option<String>,             // 年级，枚举见 2.2
    #[serde(default)]
    pub school: Option<String>,            // 学校（可选）
    #[serde(default)]
    pub avatar: Option<String>,            // 头像：emoji 或色板索引（"c0".."c7"）
    // 原有 created_at_ms / last_used_at_ms 不变
}
```

存注册表层（而非账套内部）的理由：主界面展示当前学生信息只需读 `profiles.json` 一处，不必等账套加载；且"未填身份的账套"也走同一数据结构。

### 2.2 年级枚举（对齐作文批改现有 `grade_level`，不另造一套）

`primary_4 / primary_5 / primary_6 / junior_1 / junior_2 / junior_3 / senior_1 / senior_2 / senior_3 / college / other`
（作文批改 `essay_grading.grade_level` 现有枚举为子集，映射关系在联动层做，见 2.4）

### 2.3 新增/修改的 Tauri 命令

- **`profile_update`**（新）：更新学生身份字段（姓名/年级/学校/头像），校验长度与枚举，写注册表（复用现有互斥锁 + 原子写路径）。
- **`profile_list`**（改）：返回结构带新字段（前端已有 `ProfileInfo` 接口同步扩展）。
- 切换继续用 `profile_switch`（重启语义不变）。

### 2.4 年级联动

- 作文批改：`EssayGradingWorkbench.tsx` 初始化 `grade_level` 时，若账套已设 `grade` 则以其为默认值（映射：junior_1→junior 等，按现有枚举取最近档）；用户在批改页仍可临时覆盖，但不再各自为政。
- 画像注入：见第四节。

## 三、主界面「当前学生」标识与切换

### 3.1 展示位：侧栏底部条（v1 只做这一处）

`ModernSidebar.tsx` 底部现有 AppMenu 条改为两段式：

```
┌──────────────────────────────────────┐
│ [🧑‍🎓 张三·初二 ▾]        [⚙ 菜单] │
└──────────────────────────────────────┘
```

- 左段：头像（emoji 或首字 + 色板底色）+ 学生名 + 年级徽章，`▾` 表示可点。
- 未设置身份的账套显示"设置学生信息"引导文案（首次点击直接跳设置）。
- 顶栏 v1 不加（学习桌面隐藏侧栏的场景后续再看），避免重复入口。

### 3.2 切换弹层（popover）

点击学生条弹出：

```
┌─────────────────────────┐
│ 👦 张三 · 初二     ✓当前 │
│ 👧 李四 · 小五           │
│ ＋ 新增学生…             │
│ ⚙ 管理学生档案…          │  → 跳设置 ProfilesTab
└─────────────────────────┘
```

- 点非当前学生 → **确认弹窗**（说明"切换将重启应用，数据各自独立保存"）→ `profile_switch` → 复用 ProfilesTab 现有的 `restarting` 转场态。
- 「新增学生」直接跳设置（创建含填表，不在弹层内做迷你表单，v1 简化）。

### 3.3 i18n / 主题红线

- 所有文案 `src/locales/zh-CN/` + `en-US/` 双份（`sidebar.json` 命名空间）。
- 头像色板走现有 CSS 变量，不硬编码深色。

## 四、AI 个性化注入（身份进 system prompt）

`learner_profile.rs` 注入会话 system prompt 的段落前，追加一行身份头（读取注册表当前账套的学生字段）：

```
【当前学生】张三，初中二年级（junior_2），就读于 XX 中学
【学习者画像】（现有 weak_points / preferences / goals 内容不变）
```

- 实现：注入点所在处能拿到 `AppHandle`（或经由既有状态传入），读 `profiles.json` active 项即可，不新增异步 IO。
- 效果：AI 对话、出题、错题讲解、作文批改全链路自动按年级调整措辞与难度，无需各处单独传参。

## 五、设置页「学生档案」

### 5.1 形态：升级现有 ProfilesTab（不新开 Tab）

理由：账套 = 学生，拆两个页面反而割裂。Tab 标题与导航文案改为「学生档案 / Students」。

每个账套卡片扩展为可编辑表单（`settingsTabPrimitives` 组件）：

```
┌─ 当前使用 ────────────────────────────────┐
│ [头像选择：emoji 行 + 8 色板]              │
│ 学生姓名  [张三        ]                   │
│ 年级      [初中二年级 ▾]                   │
│ 学校      [XX中学     ]（可选）            │
│ 账套名称  [默认账套    ]（原 rename 功能）  │
│ [保存]  [切换到此学生]  [删除]             │
└──────────────────────────────────────────┘
```

- 保存调 `profile_update`；切换/删除沿用现有逻辑与确认弹窗。
- 下方加一个只读小节「学习者画像」：展示 `memory_get_profile` 返回的薄弱点/偏好/目标摘要 + "由 AI 在使用中自动积累，也可在对话中直接告诉它"提示（v1 只读，编辑走对话工具，避免重复造画像编辑器）。

## 七、风险与红线

1. **切换 = 重启**：弹层文案必须明示，且切换前应用自身的自动快照要已落盘（现有机制已保证，弹窗兜底提示）。
2. **serde 兼容**：新字段全部 `#[serde(default)]`，旧 profiles.json 直接可读；`profile_update` 只写存在的字段。
3. **ACL 坑**：`profile_update` 是新 `#[tauri::command]`，必须登记 `src-tauri/permissions/application-commands.toml`（历史踩坑 2 次）。
4. **隐私**：姓名/学校仅存本地注册表，不上传、不进同步备份的白名单之外（数据治理备份已整目录打包，无需额外处理）。
5. **作文批改枚举映射**：`junior_2` 这类新值映射到批改页现有枚举取最近档，映射函数加单元测试。
