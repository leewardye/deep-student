# 错题订正·豆包批改能力接入方案（调研定稿）

> 2026-11-06 调研。目标：达到「桌面豆包批改作业」同级效果——上传作业/试卷照片，自动框出每道题、判对错、给解析，错题入库。

## 一、结论先行

**推荐方案 A：接入火山引擎「联网问答 Agent·教育场景」的作业批改 API**。这是豆包爱学（豆包 App 里的作业批改功能）的**同款能力官方 API 开放**，2026 年 10 月上线，直接复用字节经过市场验证的「切题 → 手写识别 → 判分 → 解析」全链路，不需要自己拼 OCR+VLM。

**否决「调用网页版豆包」**：doubao.com 网页版与桌面客户端均无官方 API，浏览器自动化路线（登录态维护、验证码、DOM 频繁改版、违反 ToS 有封号风险、截图无法拿到坐标数据）不可作为产品能力，仅适合个人临时手动使用。

## 二、候选方案对比

### 方案 A：火山引擎联网问答 Agent·教育场景（⭐推荐）

豆包爱学同款，官方 API，异步任务制：

| 项目 | 内容 |
|---|---|
| 提交接口 | `POST https://open.feedcoopapi.com/agent_api/agent/home_work/mark/submit`（AK/SK 走 TOP 网关 `HomeWorkMarkSubmit`） |
| 查询接口 | `.../home_work/mark/query`（建议查询间隔 >2s，任务 7×24h 内可查） |
| 输入 | `image_base64`（DataUrl，推荐 ≤500KB，支持 JPEG/PNG/HEIC 等）或 `image_url`，`bot_id`（控制台创建智能体获得） |
| 输出 | 每道题：`mark_points`（**四角坐标**，基于矫正后图片）+ `question_type`（选择/填空/口算/解答等 12 类）+ `answer_results[]`（每个**手写答案**的四角坐标 + `correct` 布尔判分）+ `solution`（Markdown+LaTeX 答案解析）+ 整页 OCR（印刷/手写逐行、**字符级坐标**）+ 学科/学段自动识别 |
| 附加开关 | `enable_image_dewarp`（矫正，默认开）、方向检测（默认开）、`enable_cross_judge`（跨栏题识别） |
| 限流 | 提交 60 RPM（账号维度） |
| **开通条件** | ① 火山引擎账号开通**联网问答 Agent Pro 版**；② 商品信息-增值服务里开通**教育场景** |
| **计费** | 后付费日结：输入 0.015 元/千 token、输出 0.043 元/千 token；**切题能力在批改服务内免费**。实测样例一页 3567 token ≈ **0.06 元/页** |
| 图片链接时效 | `preprocessed_image_url` 仅 7 天有效，**需自行转存**（坐标基于矫正后图片，展示也应转存该图而非原图） |

### 方案 B：火山方舟 doubao-seed 视觉模型 + Grounding 自建（备选兜底）

直接调方舟 `doubao-seed-2-1-pro` 等 vision 模型：grounding 能力可输出 bbox 坐标（原生 bbox 标签或 `image_process` 工具 `grounding: enabled`），配合自写 prompt 做「框出错误答案」。优点是只需一个 ARK API Key（项目 OCR 链路已在用同平台模型，基础设施零新增）；缺点是**没有豆包爱学的教育专调**——切题、手写答案定位、对错判分、口算/竖式等题型支持都要自己拼 prompt 自己兜底，效果上限明显低于方案 A。

**定位**：作为方案 A 的降级路径（教育场景未开通/欠费时），且与现有 `dstu-llm` OCR 分流架构天然兼容。

### 方案 C：豆包网页版/桌面客户端自动化（❌否决）

- 无官方 API，网页需扫码登录，自动化属违反用户协议，有封号风险；
- 界面 DOM 频繁改版，脚本极脆；
- 只能拿截图/文本，**拿不到结构化坐标**，无法在原图上精确画红框、无法结构化入库。

## 三、deep-student 落地设计（0.15.x「错题订正工作台」）

### 数据流

```
拍照/选图 → (Rust) 压缩≤500KB → mark/submit → task_id
         → 轮询 mark/query(≥2s 间隔) → success
         → 下载 preprocessed_image 转存本地（7 天时效）
         → 前端：矫正图 + SVG 覆盖层（题目四角框 / 手写答案框 / ✓✗ 标记）
         → 点开某题：solution 渲染（现有 Markdown+KaTeX 管线）
         → 一键「收入错题本」：correct=false 的题按 mark_points 裁图
           + solution + 学科/学段/题型 写入 mistakes.db
```

### 模块划分

| 层 | 内容 |
|---|---|
| Rust 新命令 | `homework_mark_submit` / `homework_mark_query` / `homework_mark_result_save`（HTTP 客户端复用现有 reqwest 配置；API Key 沿用现有设置存储，**注意不要明文进前端**） |
| 设置页 | 联网问答 Agent 开关 + API Key/AK-SK + bot_id 配置项；未配置时入口灰显引导 |
| 新 Tab/页面 | 错题订正工作台：图片上传 → 批改进度 → 左图右解析双栏 → 错题勾选入库 |
| 错题本 | mistakes.db 增加来源字段 `source=homework_mark`、`mark_id`、`crop_path`；与现有错题浏览/复习打通 |
| 讲题追问 | 复用拍题答疑（`extension_options.learn_mode=auto_learning`）做「这题再讲讲」，二期接入 |

### 关键坑位（提前记）

1. **坐标基于矫正后图片**，必须转存 `preprocessed_image_url` 并用它做展示底图，不能用原图（坐标会对不上）；
2. `finish=false` 的题目字段不完整，前端要等 `finish=true` 再渲染解析；
3. 跨栏题 `cross_question=true` 时多题共享结果，UI 需按 `cross_mark_id` 归组；
4. 转存失败兜底：7 天后链接失效，本地必须有副本；
5. 开通教育场景增值服务是否需要企业实名认证**待实际开通验证**（个人账号先试）。

### 分期

- **0.15.0**：方案 A 全链路（上传→批改→画框→解析→错题入库）+ 设置页配置；
- **0.15.x**：拍题答疑追问、错题裁图归档优化；
- 兜底：方案 B 接入 `dstu-llm` 作为备用 provider（与 OCR 分流同一套 candidates 机制）。
